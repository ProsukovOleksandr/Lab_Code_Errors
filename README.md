# Lab_Code_Errors
№1
1) Класс UserManager виконує багато різних завдань одночасно, що порушує принцип єдиної відповідальності.
2) Поле password, що зберігає пароль ніяким чном не захищається і не шифрується, що створює небезпеку для даних користувача.
3) Відсутні будь які перевірки на правильність введених даних.

№2
1) Код не адаптовано під додавання в майбутньому нових способів оплати. Щоб це зробити, доведеться переписувати код, і додавати нові поля.
2) Для кожного сапособу оплати варто використовувати окремий клас, а класс PaymentProcessor використовувати для спільного виконання і реалізації.

№3
Метод fly визначений як обов'язкова інструкція для всіх дочірніх елементів классу Bird, тому використання цього классу для створення єкземпляра з твариною, що не здатна літати, є недоречним.
Доцільніше зробити в класі Bird методи, фкі описують загальну поведінку і характеристики всіх птахів, такі як рук чи харчування, а потім додати додаткові рвівні с з розділення на літаючих і нелітаючих, чи інших, в залежності від вимог.

№4
Класс RobotWorker лише один з трьох методів інтерфейсу Worker, тому використання цього інтерфейсу є недоречним.

№5
Жорсткі залежності в коді ускладнюють процес модифікації ми покращення коду в майбутньому, якщо наприклад доведеться змінити СУБД. Для цього доведеться повністю змінювати логіку роботи. Також це ускладнює тестування, оскільки модуль OrderService напряму залежить від інших низкорівневих модулів, що порушує принцип залежності від абстракцій.
